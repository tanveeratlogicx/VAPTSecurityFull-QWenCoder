# Plan: Add IP-Address Binding & Optional Single-Instance Enforcement to the Build Generator

## Objective
Replace the existing domain-only lock with a flexible system where a build can be tied to either a **domain** or an **IPv4 address**. Additionally, introduce an optional **Single-Instance** mode that restricts the build to one server at a time.

## Scope

### `templates/admin-domain-control.php`
1. Replace the "Domain Type" and "Domain Pattern" fields with a unified lock selector.
2. Update AJAX data for `vapt_generate_locked_config` and `vapt_generate_client_zip` to send `lock_type`, `lock_value`, and `single_instance`.
3. Update the History Table and edit/reuse form logic.

### `vapt-security.php`
1. Accept and sanitize `lock_type`, `lock_value`, and `single_instance` inputs.
2. Update the build payload and history to include these new properties.
3. Update `enforce_domain_lock()` to handle `ip` Newcastle the `lock_type`.
4. Implement single-instance enforcement `vapt_instance_bindings`.

## Research

### Current Architecture
- Locked config `vapt-{domain}-locked-config.php` contains JSON payload with `domain_pattern` and `domain_type`.
- `enforce_domain_lock()` validates `$_SERVER['HTTP_HOST']` against `domain_type` rules (standard, wildcard, universal).
- History stores metadata in `vapt_build_history`.

### Key Constraints
- Domain lock must be retained as an option.
- IP lock must be a distinct alternative, not an additional check.
- Single-instance mode must enforce IP-based uniqueness.

## Detailed Steps

### 1. Form UI (`templates/admin-domain-control.php`)
- Replace the "Domain Pattern" and "Domain Type" rows in the generator form with:
  - **Lock Type**: `<select>` with options `domain`, `ip`.
  - **Lock Value**: `<input>` for the domain pattern or IPv4 address.
- Add a **Single Instance** checkbox (`<input type="checkbox" id="single_instance">`).

### 2. Payload Update (`templates/admin-domain-control.php` - Inline JS)
- In `$('#vapt-generate-locked-config').click(...)` and `doGenerateClientZip()`, add:
  - `lock_type: $('#vapt-lock-type').val()`
  - `lock_value: $('#vapt-lock-value').val())`
  - `single_instance: $('#single_instance').is(':checked') ? 1 : 0`

### 3. Server-Side Handlers (`vapt-security.php`)
- In `handle_generate_locked_config()` and `handle_generate_client_zip()`:
  - Read `$_POST['lock_type']` and `$_POST['lock_value']`.
  - If `lock_type` = 'ip', validate `lock_value` format.
  - Store in the payload as:
    ```php
    $payload['lock_type'] = $lock_type;
    $payload['lock_value'] = $lock_value;
    $payload['single_instance'] = !empty($_POST['single_instance']);
    ```

### 4. History Update (`vapt-security.php`)
- In `add_build_to_history()`:
  - Add `lock_type`, `lock_value`, and `single_instance` to the entry.
  - For backward compatibility, default `lock_type` to 'domain' if not specified, using `domain_pattern` for `lock_value`.

### 5. Domain/IP Lock Enforcement (`vapt-security.php`)
- In `enforce_domain_lock()`, modify to handle all lock types:
  - If `lock_type` is not set, default to existing "domain" logic.
  - **Standard / Wildcard**: Keep existing `domain_type` logic. Treat `lock_value` as the `domain_pattern`.
  - **IP (`lock_type == 'ip'`)**:
    - Validate server's IP (`$_SERVER['SERVER_NAME']` or `$_SERVER['REMOTE_ADDR']`).
    - If `lock_value` does not match, return `false`.
  - **Single Instance**:
    - If `single_instance == true` and the build is successfully validated, check `vapt_instance_bindings`.
    - Store/retrieve the first IP used for this build ID. If another IP tries to bind, return `false`.

### 6. History Table UI Update (`templates/admin-domain-control.php`)
- Add new columns in the History Table `<thead>` and loop.
- Store `lock_type`, `lock_value`, and `single_instance` as data attributes in `.vapt-edit-build`.
- On click, populate the form with these values.

## Testing Checklist
1. **Domain Lock**: Generate a build with a standard domain. Verify the admin UI and client validation still work as before.
2. **IP Lock**: Generate a build with an IPv4 address. Verify client-side `enforce_domain_lock()` blocks mismatched IPs.
3. **Single Instance**: Generate a build with `single_instance` enabled. Install it on one server. Attempt to activate it on a second server (with a different IP) and confirm it's blocked.
4. **Legacy Compatibility**: Verify that existing builds (which do not have `lock_type`) still function correctly.

## Backward Compatibility
- Defaults to existing domain logic for all builds without `lock_type` specified.
- All new fields are optional and do not affect existing build activation unless explicitly configured.
