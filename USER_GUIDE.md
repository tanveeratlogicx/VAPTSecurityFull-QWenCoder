# VAPT Security - User Guide

This guide provides an overview of the security features enabled by the VAPT Security plugin and instructions on how to verify they are working.

## Features & Verification

### 1. Login Rate Limiting (V#1)
**What it does:**
Prevents brute-force attacks on `wp-login.php` by limiting the number of failed login attempts from a single IP address within a 15-minute window.

**How to Verify:**
1.  Go to your login page: `https://vaptsecure.local/wp-login.php`
2.  Attempt to log in with an incorrect password 6 times.
3.  **Result:** On the 6th attempt, you should be blocked and see an error message: "Too many failed login attempts. Please try again later."
4.  *Note:* Your IP will be temporarily blocked from further login attempts.

### 2. WP-Cron Protection (V#2)
**What it does:**
Protects your site from Denial of Service (DoS) attacks targeting the `wp-cron.php` file. It blocks external requests to this file unless they come from authorized IP addresses or exceed the hourly rate limit.

**How to Verify:**
1.  Open your browser and visit: `https://vaptsecure.local/wp-cron.php`
2.  Refresh the page repeatedly until the limit is reached.
3.  **Result:** You should see a "Too many requests" / 403 error message, indicating that access is blocked.

### 3. XML-RPC Protection (V#3)
**What it does:**
Disables the XML-RPC functionality to prevent SSRF and brute-force attacks.

**How to Verify:**
1.  Attempt to access `https://vaptsecure.local/xmlrpc.php` in your browser or via a POST request.
2.  **Result:** You should see a 403 Forbidden error with the message "XML-RPC is disabled for security reasons."

### 4. Directory Listing Protection (V#4)
**What it does:**
Prevents attackers from listing files in sensitive directories like `wp-content/uploads/`.

**How to Verify:**
1.  Navigate to `https://vaptsecure.local/wp-content/uploads/` in your browser.
2.  **Result:** You should see a blank page or a 403 Forbidden error instead of a list of files.

### 5. Contact Form Rate Limiting (V#5)
**What it does:**
Prevents spam and automated submissions by limiting the number of requests a single IP can make to form endpoints.

**How to Verify:**
1.  Submit a contact form multiple times in quick succession.
2.  **Result:** After exceeding the limit, subsequent submissions will be blocked with a "Too many requests" error.

### 6. Banner Grabbing Protection (V#6)
**What it does:**
Hides version information for WordPress, PHP, and other software from response headers and source code.

**How to Verify:**
1.  Check response headers for `X-Powered-By`.
2.  View the page source and search for `<meta name="generator" content="WordPress ...">`.
3.  **Result:** These version identifiers should be missing.

### 7. REST API Username Enumeration Protection (V#7 & V#10)
**What it does:**
Restricts unauthenticated access to sensitive REST API endpoints, preventing attackers from gathering lists of usernames or site structure.

**How to Verify:**
1.  Visit `https://vaptsecure.local/wp-json/wp/v2/users` while logged out.
2.  **Result:** You should see a 401 Unauthorized error: "Authentication required."

### 8. Generic Login Errors (V#8)
**What it does:**
Prevents username enumeration via `wp-login.php` by showing the same error message regardless of whether the username exists.

**How to Verify:**
1.  Attempt to log in with a non-existent username.
2.  Attempt to log in with a valid username but incorrect password.
3.  **Result:** Both attempts should result in the identical message: "Invalid username or password."

### 9. Security Headers / Clickjacking (V#11)
**What it does:**
Adds HTTP security headers to protect against clickjacking and other browser-based attacks.

**How to Verify:**
1.  Use a tool like `securityheaders.com` or check your browser's Developer Tools (Network tab).
2.  **Result:** You should see headers like `X-Frame-Options: SAMEORIGIN` and `X-Content-Type-Options: nosniff`.

### 10. Sensitive File Protection (V#12 & V#13)
**What it does:**
Blocks access to sensitive files like `debug.log` and `readme.html`.

**How to Verify:**
1.  Navigate to `https://vaptsecure.local/wp-content/debug.log` (if it exists).
2.  Navigate to `https://vaptsecure.local/readme.html`.
3.  **Result:** Both should return a 403 Forbidden error.

### 11. Input Validation (V#14)
**What it does:**
Sanitizes and validates incoming data to prevent XSS and SQL Injection attacks.

**How to Verify:**
1.  Try to submit a form with a test script tag, e.g., `<script>alert('test')</script>`.
2.  **Result:** The script tags will be removed or encoded, preventing execution.
