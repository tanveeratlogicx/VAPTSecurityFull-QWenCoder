# BUILD-TRACKING-IMPLEMENTATION-PLAN.md

## Overview

This plan implements the Build Tracking & Callback System described in `BUILD-TRACKING-PLAN.md`. The system monitors build activations, license status, and versioning across client domains, sending data back to `https://vaptsecure.net/vapts` and displaying it in a new **Build Tracking** tab on the Domain Admin page.

## Prerequisites

- **Production WordPress** must be running `VAPTSecurity-Full/vapt-security.php` v3.2.1 (currently running v2.11.0)
- **All locked-config files** must be regenerated via the Build Generator after v3.2.1 deployment
- **Local development environment** should also be updated to v3.2.1

## Implementation Steps

### Phase 1: Foundation Setup

#### 1.1 Deploy v3.2.1 to Production
- Replace `VAPT-Secure/vaptsecurity.php` with `VAPTSecurity-Full/vapt-security.php` v3.2.1
- Update `VAPT_VERSION` constant to `3.2.1`
- Bump plugin header `Version:` to `3.2.1`
- Bump `package.json` version to `3.2.1`
- Create `VERSION_HISTORY.md` documenting changes

#### 1.2 Fix Blocking Ping Issue
- Change `wp_remote_post` call in `maybe_trigger_callback()` from `blocking: true` to `false` (line 2842)
- This prevents page load delays on client sites

#### 1.3 Add HMAC Payload Protection
- In `maybe_trigger_callback()`, generate HMAC signature for the ping payload using `hash_hmac('sha256', json_encode($payload), $salt)`
- Add `sig` field to the payload
- In `handle_build_callback()`, verify the signature with `hash_equals()` before processing data

### Phase 2: Build Tracking Infrastructure

#### 2.1 Re-generate Locked Configs
- Use the Build Generator in `admin-domain-control.php` to create fresh locked-config files for all domains
- Ensure each config includes: `build_id`, `integrity_url`, `tracking_mode`, `license`, `white_label.version`
- Do NOT hand-edit PHP files; use the generator UI

#### 2.2 Fix Email Notifications
- Update `send_license_notification_email()` to send to `tanmalik786@gmail.com` instead of `get_option('admin_email')` (line 2967)

#### 2.3 Add Custom Term Remote Action
- Extend Remote Management modal in `admin-domain-control.php` with an expiry date picker
- Add `EXTEND_CUSTOM` command type in `handle_push_remote_command()`
- Implement custom expiry logic in `process_remote_commands()`

#### 2.4 Add Authoritative Tracking on Client
- In `maybe_trigger_callback()`, check if `first_activation` is already set in `vapt_build_tracking` on the Master
- If set, use that value instead of local `vapt_initial_install_time`
- This prevents re-installation from resetting the urgency sequence

### Phase 3: Testing & Documentation

#### 3.2 Bump Versions and Finalize

## Discoveries

- **Production vs Dev Plugin Mismatch**: The production WordPress runs `VAPT-Secure/vaptsecurity.php` v2.11.0 (no tracking), while the development copy is `VAPTSecurity-Full/vapt-security.php` v3.2.1 (with tracking). This is the root cause of the empty Build Tracking tab.
- **Locked Configs Missing Tracking Fields**: Three of four locked-config files (vaptsecure, wptest, vapt-locked-config) were generated before tracking fields existed; they lack `build_id`, `integrity_url`, `tracking_mode`, and `license` data.
- **Blocking Ping Issue**: `maybe_trigger_callback()` uses `wp_remote_post` with `blocking => true` and a 15-second timeout, causing page load delays on every client page load.
- **Missing HMAC on Callback Payload**: The client-to-Master ping payload has no HMAC signature, making it vulnerable to tampering.
- **Email Recipient Issue**: `send_license_notification_email()` sends to `get_option('admin_email')` instead of `tanmalik786@gmail.com`.
- **Custom Term Missing**: The Remote Management modal lacks an expiry date picker and `EXTEND_CUSTOM` command handler.
- **Authoritative Tracking Not Fully Enforced**: `first_activation` is immutable on Master, but client re-installation can still reset the local clock because `maybe_trigger_callback()` does not check the Master's stored value.
- **Version Inconsistencies**: Plugin header, `package.json`, and `VERSION_HISTORY.md` need updates to `3.2.1`.
